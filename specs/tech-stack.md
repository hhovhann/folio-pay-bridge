# Tech stack

Chosen to match the job posting, one line of reasoning each.

| Area | Choice | Why |
|---|---|---|
| Language | Java 17 (records, switch expressions, `instanceof` patterns) | Posting: Java 17 |
| Framework | Spring Boot 3.5, Spring MVC, Bean Validation, Actuator | Posting: Spring |
| Persistence | Spring Data JPA on Hibernate; H2 (PostgreSQL mode) for demo and tests, PostgreSQL profile for real runs | Posting: Hibernate. Unique constraints carry the idempotency guarantees |
| Keys and secrets | AWS SDK v2 `KmsClient` (synchronous, `apache5-client`; the unused async Netty client is excluded; `KmsWireTest` runs the real client over HTTP): `GenerateDataKey` AES-256, encryption context = token id; local in-memory master key for demo and tests | Posting: keys in KMS. Credentials come from the instance or task role, never from config |
| Crypto | AES-256-GCM, 96-bit random IV, token id as associated data | A ciphertext cannot be moved to another token |
| API description | springdoc-openapi 2.8.17 (`webmvc-ui`; 3.x targets Spring Boot 4), added with the owner's approval | The spec is generated from the controllers and DTOs, so it cannot drift; `docs/openapi.json` is the committed copy and `OpenApiContractTest` fails if they differ. Off by default, on in the demo profile (OWASP A05) |
| Retry | Resilience4j `resilience4j-retry` 2.2.0 (added with the owner's approval) | Tested, configurable backoff with jitter instead of a hand-written loop; no Spring AOP needed, so it stays a plain injected bean |
| Structure | Layers: api, service (interface + impl), domain, repository, gateway, crypto | Dependencies point inward; see D-14. `ArchitectureTest` reads the import lines and fails the build when a layer reaches past its neighbour, and `CodeConventionsTest` checks import order, braces, inline class names, field injection and console output (no library needed; ArchUnit, Checkstyle or Spotless would be the next step if the rules grow) |
| API | Path versioning (`/api/v1`, `ApiPaths`), `@ApiDeprecation` adds `Deprecation`, `Sunset` and a successor `Link`; RFC 9457 problem details (Spring's `ProblemDetail`) with a stable `code` | What payment APIs do (Stripe `/v1`, Adyen `/v71`); the standards a client's tooling already parses (D-39, D-29). Spring Framework 7's built-in versioning comes with Spring Boot 4 |
| Coverage | JaCoCo 0.8.12 (added at the owner's request): report at the end of `./mvnw test`, gate in `./mvnw verify` at 99% lines and 90% branches; `python3 tools/coverage.py` lists what is uncovered | A measured number instead of a claim. Excluded: the two `main()` entry points only |
| Authentication | Spring Security 6.5 with `spring-boot-starter-oauth2-resource-server` (added with the owner's approval, 2026-11-18): OAuth2 client-credentials JWTs checked against the authorization server's JWKS (signature, issuer, audience, expiry, scopes), plus scoped API keys stored as SHA-256 hashes | What payment APIs do (OAuth2 client credentials; restricted, hashed API keys for integrators that cannot do OAuth2). A framework that is reviewed and patched instead of a hand-written filter (D-30) |
| Schema migrations | Flyway (`flyway-core`, `flyway-database-postgresql`, added with the owner's approval, 2026-11-18); Hibernate `validate` on PostgreSQL | The schema is reviewed SQL under version control, applied before the code that needs it (D-12) |
| Edge hardening | Request id, security headers, a host allowlist and a 1 MB body limit as small servlet filters | Each tested on its own; Spring Security's own header writer is off so there is one owner of the headers |
| Operator dashboard | React 18.3 + TypeScript 5.6, built with Vite 7.3; tests with Vitest 4.1 and Testing Library; `oidc-client-ts` 3.1 for sign-in; built and tested by Maven through `frontend-maven-plugin` 1.15 with Node 22 pinned (all added with the owner's approval, 2026-11-18) | The most common choice a reviewer will know; lighter than Angular for five screens; pinned versions and a lock file, so the build is the same everywhere. No UI kit: one stylesheet with light and dark tokens (D-38) |
| Browser checks | Playwright (Python, in `demo/`): `demo/check_dashboard.py` drives the real dashboard against the running app and fails on any browser error, including content security policy violations | A UI is proven in a browser, not only in a DOM simulator |
| AI guardrails | `tools/guard_secrets.py` and `tools/guard_commands.py` (standard-library Python) as Claude Code `PreToolUse` hooks and CI steps; project permission rules in `.claude/settings.json` | The `CLAUDE.md` hard rules enforced by the tooling, not only by the reader (D-36); the command guard reads every argument, because permission rules match prefixes only |
| Logging | Logback with a `%msg` converter that redacts card numbers (Luhn-valid 13 to 19 digit runs), card tokens, credentials and secret fields (`LogRedactor`); an audit trail on its own logger (D-43); in production `logback-json.xml`, one masked JSON object per line (`MaskedJsonEncoder`, Jackson, no new dependency) with the request id and client as fields | Posting: nothing sensitive in logs. JSON lines are what CloudWatch Logs Insights queries; INFO for state changes, DEBUG for decisions, never card data or tokens (D-41) |
| Tests | JUnit 5, AssertJ, Mockito, Spring Boot Test, MockMvc. Unit tests per rule and service (fast, no Spring); `@WebMvcTest` for the HTTP contract; a small `integration` package on H2 for what only a real database proves (constraints, versions, races) | Each test names the failure it would catch |
| OHIP contract check (test only) | networknt `json-schema-validator` 2.0.4, added with the owner's approval (2026-11-18) | Checks every exchange between the OPERA adapter and the simulator against Oracle's published OHIP Swagger files (D-42). Small (Jackson and a date parser); 2.0.4 is the last release on a Jackson older than the one Spring Boot manages, so the enforcer's upper-bound rule holds (2.0.5+ asks for Jackson 2.22, 3.x is built on Jackson 3). *Considered:* Atlassian's `openapi-request-validator`, made for exactly this, rejected for what it brings: two Swagger parsers, Guava and a JavaScript engine, in a payments build |
| Dependency scanning (CI only) | Google's OSV-Scanner as a reusable GitHub workflow, v2.7.1 pinned to its commit, added with the owner's approval (2026-11-21) | Known advisories in the Maven dependencies (transitive included) and the dashboard's lock file, on every push and weekly; accepted ones are listed with their reasons in `osv-scanner.toml` (D-46, PCI DSS 6.3). No API key, seconds per run; OWASP Dependency-Check was the alternative |
| Build | Maven wrapper; `maven-enforcer-plugin` (version managed by Spring Boot) with dependencyConvergence and requireUpperBoundDeps | No jar hell: a version conflict fails the build at `validate`. Four Boot-managed versions (httpclient5, httpcore5, snakeyaml, commons-lang3) are raised to what their users were built against, each with a test that runs it |
| Runtime | Amazon Corretto 17 on the Amazon Linux 2023 image (`amazoncorretto:17-al2023`, headless at run time); any OpenJDK 17 for development (the author's machine uses Temurin) | Posting: AWS, Amazon Linux 2023. Corretto is Amazon's OpenJDK build and the JDK that Amazon Linux 2023 itself ships (`dnf install java-17-amazon-corretto`), with Amazon's long-term security updates and AWS support; Eclipse Temurin publishes no Amazon Linux image (its images are Ubuntu and UBI). Both pass the Java TCK, so the code behaves the same on either |
| Demo | Playwright + local Kokoro voice + ffmpeg | Narrated video from the real app |
